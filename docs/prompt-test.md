# 프롬프트 시험 기록 (plan 3-8)

갤러리가 만든 프롬프트만 주고, 코드와 문서에 접근하지 못하는 저가 모델에게 일을 시킨 뒤 결과를 실제 Unity 로 컴파일하고 촬영했다.

- 일시: 2026-11-02. API 키가 아직 없어 구독 서브에이전트(Claude Haiku 5.5)로 시험했다. API 연결 뒤 4단계에서 다시 잰다.
- 프롬프트: `node tools/prompt-case.mjs <id> <종류> <출력 파일> [대괄호 칸 내용...]`. 앱의 AI 지시 세트와 같은 함수로 만든 글이다.
- 서브에이전트 지시: 프롬프트 파일만 읽는다. 다른 파일을 읽거나 검색하지 않는다. Bash 금지. 결과 파일을 지정한 폴더에 쓴다.
- 판정: 복사본 프로젝트의 원래 파일에 결과를 덮어쓰고 `SgVerify` 로 D3D11, Vulkan, GLES3, Metal 컴파일과 C# 컴파일, 촬영. 스크린샷은 눈으로 봤다.

## 시험에서 나온 수정

- 변형 답변 넷 중 셋이 "웹 미리보기 쪽은 확인하지 못했다"는 주의를 붙였다. `core.hlsl` 주석의 웹 언급을 보고 걱정한 것이다. 수강생에게는 필요 없는 말이므로 프롬프트에 `SG_STEP`, `SG_OFF`, 웹 언급은 무시해도 된다는 안내를 넣었다.
- 시험 전에 금지 사항 문구를 고쳤다. "URP `ShaderLibrary` 만 쓴다"는 문구가 샘플의 `Core2D.hlsl`, `Blit.hlsl` include 와 어긋났다.

## 3-9 수정 뒤 재시험

리뷰 반영으로 샘플 코드와 프롬프트가 바뀌어 디졸브 변형 한 건을 다시 돌렸다. 인스턴싱, 스테레오, 그림자 키워드까지 넓힌 컴파일 80개가 모두 통과했고, 화면도 요청대로 발밑부터 청록 띠가 올라갔다. `UniversalForwardOnly` 패스 태그도 그대로 유지했다.

위 안내를 넣었는데도 답변에 웹 uniform 을 추가하라는 한 줄이 남았다. 안내를 "이 프로젝트에는 웹 미리보기가 없으니 웹 쪽 수정이나 주의 사항은 적지 않는다"로 더 분명하게 바꿨다. 이 마지막 문구는 다시 시험하지 않았다. 남아도 해가 없는 한 줄이다.

## 시험하지 않은 것

- 사람이 실제 프로젝트의 메시와 씬에 넣는 과정. 시험은 파일 수준에서 샘플 폴더를 덮어썼다.
- '그대로 넣기' 프롬프트. 코드를 바꾸지 않는 프롬프트라 컴파일 결과는 샘플과 같다.
- 숨 쉬는 외곽선처럼 시간에 따라 변하는 동작.
- Haiku 외의 모델. 4-2 에서 비교한다.

# 스프라이트 바람 흔들림 (Sprite Wind Sway)

풀 스프라이트의 위쪽만 바람에 흔든다

무대 종류: 스프라이트. 난이도 2/3. 기법: 정점 변형, 스프라이트, UV 마스크, 노이즈, 화면 미분.

## 파일
- `SpriteWindSway.shader`
- `core.hlsl`
- `GrassPush2D.cs`
- `SpriteWindSwayGrass.png`

모두 프로젝트의 `Assets/Shaders/sprite-wind-sway/` 에 복사한다.

## 넣는 순서
1. `SpriteWindSway.shader`, `core.hlsl`, `GrassPush2D.cs` 를 `Assets/Shaders/sprite-wind-sway/` 에 둔다.
2. 풀 PNG(예: `SpriteWindSwayGrass.png`)의 임포트 설정을 Texture Type Sprite (2D and UI), Sprite Mode Single, Mesh Type Full Rect, sRGB 켬, Wrap Mode Clamp, Filter Mode Bilinear, Pixels Per Unit 64 로 하고 Apply 한다. 텍스처 높이 128px 가 2 유닛이 되어 웹 무대와 같은 크기다. 그림 둘레에 투명 여백을 두고 Sprite Atlas 에는 넣지 않는다.
3. Project 창에서 셰이더를 우클릭해 Create > Material 로 머티리얼을 만든다. 덤불이 여러 개여도 머티리얼 하나면 된다. 자리마다 박자는 셰이더가 월드 x 로 정한다.
4. 덤불마다 SpriteRenderer 의 Material 칸에 이 머티리얼을 넣는다. 덤불마다 색을 조금 바꾸려면 SpriteRenderer 의 Color 를 쓴다 (정점 색으로 들어가 곱해진다).
5. 지나가는 캐릭터에 밀리게 하려면 덤불에 Box Collider 2D 를 붙여 Is Trigger 를 켜고 `GrassPush2D` 를 붙인다. Pushers 에 플레이어 레이어를 고른다. 플레이어에는 Rigidbody 2D 와 Collider 2D 가 있어야 트리거가 불린다.

## 확인
바람 세기를 올리면 덤불 위쪽이 더 크게 좌우로 출렁이고 뿌리는 땅에 붙어 있으며, 휨을 0 으로 내리면 잎이 곧은 채 평행사변형으로 기운다. 같은 머티리얼의 덤불을 가로로 여럿 놓으면 저마다 다른 박자로 흔들리고, 플레이어가 지나가면 그 덤불만 지나간 쪽으로 한 번 휘청인다.

## 기본 머티리얼 값
| 속성 | 뜻 | 값 |
|---|---|---|
| `_WindStrength` | 바람 세기 | 0.18 |
| `_Lean` | 기울기 쏠림 | 0.1 |
| `_WindSpeed` | 바람 속도 | 1 |
| `_Gustiness` | 돌풍 변화 | 0.6 |
| `_PhaseSpread` | 박자 어긋남 | 0.8 |
| `_Bend` | 휨 | 1 |
| `_Push` | 밀기 | 0 |
| `_Tint` | 색 | #FFFFFF |
| `_Shade` | 명암 | 1 |

## 동작 단계
1. **흔들림 마스크**: 정점이 바람 값에 곱하는 `uv.y` 다. 아래(뿌리)는 검고 위로 갈수록 밝아져 꼭대기가 희다. 단계 보기는 알파 없이 칠해 스프라이트의 사각형 전체가 보인다. 이 사각형은 정점 4개라 위쪽 두 꼭짓점만 옆으로 밀리고 아래 두 꼭짓점은 `uv.y` 가 0 이라 제자리다. 그래서 사각형이 휘지 않고 평행사변형으로 기운다. 위쪽 두 꼭짓점은 각자 자리의 월드 x 로 바람 값을 구해, 박자 어긋남이 크면 둘이 다르게 밀려 사다리꼴로 벌어지거나 좁아지기도 한다.
2. **바람 값 S**: 꼭대기를 미는 양 S 를 칠했다. 오른쪽으로 밀리는 곳(+)은 주황, 왼쪽(-)은 파랑이고 많이 밀릴수록 밝으며, 0 근처는 검은 띠가 된다. 잎이 있는 곳을 밝게 칠해 덤불 모양도 보인다. S 는 월드 x 에서 위상을 얻는 느린 사인에, 오른쪽으로 흘러가는 노이즈 돌풍이 세기를 곱하고, 쏠림과 밀기를 더한 값이다. 같은 순간에도 세 덤불의 색과 밝기가 다르고, 재생하면 파랑과 주황의 경계(검은 띠)가 왼쪽 덤불에서 오른쪽 덤불로 흘러간다. 바람의 마루가 +x 로 지나가는 모습이다.
3. **곧게 기울이기만**: 정점만 민 모습이다. 검은 바탕이 기운 사각형 메시다. 잎은 곧은 채 덤불 전체가 사각형과 함께 평행사변형으로 기운다. 정점이 4개뿐이라 정점 단계로는 이 이상 휘게 할 수 없다. 최종 화면은 픽셀 단계에서 높이 y 마다 `S × (y - y²)` 만큼 옆 텍셀을 읽어 되돌린다. 그러면 잎 모양은 `S × y²` 만큼 밀린 것처럼 보여, 뿌리 쪽은 서 있고 끝으로 갈수록 휜다. 월드 거리를 uv 거리로 바꾸는 비율은 `ddx(uv.x) / ddx(positionWS.x)` 로 구한다.

## 주의할 점
- 2D Renderer 에서는 `Universal2D` 패스가, Universal Renderer 에서는 `UniversalForward` 패스가 그려진다. 하나를 지우면 다른 쪽에서 풀이 사라진다. 이 셰이더는 2D 조명을 받지 않는다.
- 위상, 돌풍, 밀기 양이 모두 월드 단위다. Scale 을 3 배로 키운 큰 덤불도 꼭대기가 같은 유닛만큼 밀리므로 상대적으로 덜 흔들린다. 큰 덤불은 머티리얼을 나눠 세기를 올린다. Pixels Per Unit 도 같은 영향을 준다. 기본값 100 이면 이 표본의 덤불이 0.96×1.28 유닛으로 작아져 같은 값이 약 1.56 배 세게 보이고, 좌우 투명 여백이 0.22 유닛으로 줄어 폭풍과 밀기가 겹치면 바깥 잎이 사각형 가장자리에서 잘린다. 정점을 월드에서 밀어서 Transform 을 돌린 스프라이트도 늘 월드 가로로 밀린다. 다만 픽셀 단계 휨은 돌리지 않은 스프라이트를 전제로 한다 (돌리면 `uv.y` 가 월드 높이와, `uv.x` 가 월드 가로와 어긋나 휨이 틀어진다).
- Unity 는 스프라이트를 동적 배칭하면 정점을 월드 좌표로, SRP Batcher 경로에서는 오브젝트 좌표로 넘긴다 (Unity 이슈 UUM-15015, As Designed). 래퍼는 둘 다 월드로 옮긴 뒤 밀어 결과가 같게 했다. Unity 6.3 에서 이 표본이 실제로 어느 배칭 경로로 그려지는지는 확인하지 못했다.
- 정점을 밀어도 Renderer 의 Bounds 는 그대로라 화면 가장자리에서 기운 풀이 통째로 컬링될 수 있다.
- 픽셀 아트 풀에서는 휨 보정이 텍셀 사이를 읽어 잎 가장자리가 반짝이거나 번진다. Filter Mode 를 Point 로 하면 계단이 움직이며 끓어 보이므로 휨을 낮추거나 꺼서 정점 기울기만 쓰고, 바람 세기를 텍셀 크기의 정수배로 끊는 방법을 고려한다.
- Scene 뷰에서 흔들리지 않으면 Scene 뷰 툴바의 Effects 메뉴에서 Always Refresh 를 켠다. 편집 모드에서는 화면을 다시 그릴 때만 `_Time` 이 흐른다.

## 흔한 실수
- **덤불이 뿌리째 땅 위를 미끄러진다**: 바람 값을 모든 꼭짓점에 똑같이 더하면 뿌리도 함께 움직인다. `uv.y`(뿌리 0, 꼭대기 1)를 곱해 위쪽만 민다. 스프라이트 Pivot 이나 오브젝트 높이로 마스크를 만들면 피벗 위치와 배칭 경로에 따라 달라지므로 `uv.y` 를 쓴다.
- **여러 덤불이 모두 같은 박자로 흔들린다**: 위상을 `positionOS` 나 오브젝트 원점(`unity_ObjectToWorld`)에서 얻으면 배칭 경로에 따라 결과가 바뀐다. 동적 배칭은 정점을 월드 좌표로 합쳐 넘기고 원점은 0 이 되며, SRP Batcher 경로는 오브젝트 좌표로 넘겨 같은 프리팹이 모두 같은 값을 갖는다. 래퍼처럼 `TransformObjectToWorld` 로 월드로 옮긴 위치의 x 로 위상을 얻으면 어느 경로든 자리마다 박자가 다르다.
- **잎이 휘지 않고 평행사변형으로 기운다**: Full Rect 스프라이트는 정점이 4개라 정점을 밀면 사각형이 기울기만 한다. 마스크를 제곱해도 정점이 없으니 휘지 않는다. 픽셀 단계에서 `uv.x += S × (y - y²) × (uv 폭 / 월드 폭)` 으로 옆 텍셀을 읽어 휘게 하거나, 정점이 많은 메시(Sprite Shape, 직접 만든 메시)를 쓴다.
- **휜 잎 끝이 잘리거나 옆 그림이 끌려온다**: 픽셀 단계 휨은 사각형 안에서 옆 텍셀을 읽으므로 그림 둘레에 투명 여백이 있어야 한다 (이 표본의 96×128 텍스처는 좌우 약 20px, 위 8px). Mesh Type 이 Tight 이면 여백이 메시에서 빠져 휜 잎이 잘린다. Full Rect 로 바꾼다. Sprite Atlas 에 넣으면 uv 가 0~1 이 아니라 아틀라스 안의 작은 사각형이라 옆 스프라이트가 끌려오고 0~1 밖을 지우는 검사도 맞지 않는다 (추론, 촬영으로 확인하지 않았다). 흔들리는 풀은 아틀라스에서 빼 단독 텍스처로 둔다.
- **화면 가장자리에서 풀이 갑자기 사라진다**: 정점을 밀어도 SpriteRenderer 의 Bounds 는 원래 사각형 그대로다. 원래 사각형이 화면 밖으로 나가는 순간 화면 안쪽으로 기운 잎까지 통째로 컬링될 수 있다. 쏠림과 밀기를 더한 폭을 작게 두거나 화면 밖 여유를 두고 풀을 놓는다.

## 변형 예시
- 플레이어가 풀 사이를 지나갈 때 덤불마다 지나간 쪽으로 휘청이게 하고 싶다.
- 전역 바람 값을 하나 두어 풀밭 전체의 바람 세기를 날씨에 따라 바꾸고 싶다.
- 천장에 매달린 덩굴이나 등불처럼 위가 고정되고 아래가 흔들리게 뒤집고 싶다.
- 물속 장면에서 수초가 좌우로 쏠림 없이 느리게 출렁이게 하고 싶다.
- 픽셀 아트 풀이라 반짝이지 않게 텍셀 단위로 끊어 흔들고 싶다.

## Shader Graph 에서 쓰기
Shader Graph 의 Sprite Unlit 타깃에서 Vertex 의 Position 은 오브젝트 공간을 받는다. Position 노드(World)의 x 에 `S × UV.y` 를 더한 뒤 Transform 노드(World → Object, Position)로 바꿔 넣는다. S 는 Time 노드와 Position(World) 의 x 로 만든 Sine 과 Gradient Noise 로 같은 식을 잇는다. Fragment 의 Position(World) 은 민 뒤 위치라 이것으로 S 와 폭 비율을 구하면 위상과 휨이 래퍼와 달라진다. Vertex 에서 밀기 전 월드 x 를 Custom Interpolator 로 넘겨 Fragment 에서 쓴다. 휨 보정은 Fragment 에서 String 모드 Custom Function 에 `UV.x += S * (y - y * y) * Bend * ddx(UV.x) / ddx(PosX)` 를 옮기고(`PosX` 는 넘겨받은 밀기 전 x, 0 나누기 막기 포함), 그 UV 로 Sample Texture 2D 를 읽는다. 이 경로는 촬영으로 확인하지 않았다.

# 하프톤 망점 (Screen Halftone Dots)

밝기를 점의 크기로 바꿔 인쇄물처럼 보이게 한다

무대 종류: 전체 화면. 난이도 2/3. 기법: 전체 화면, 하프톤, 칸 중심 샘플, 안티에일리어싱, Full Screen Pass.

## 파일
- `ScreenHalftoneDots.shader`
- `core.hlsl`

모두 프로젝트의 `Assets/Shaders/screen-halftone-dots/` 에 복사한다.

## 넣는 순서
1. `ScreenHalftoneDots.shader`, `core.hlsl` 을 `Assets/Shaders/screen-halftone-dots/` 에 둔다.
2. 셰이더를 우클릭해 Create > Material 로 머티리얼을 만든다. 기본값은 바로 쓸 수 있는 약한 값(잉크 세기 0.4)이다.
3. 사용 중인 렌더러 에셋(Universal Renderer Data 또는 Renderer 2D Data)의 Add Renderer Feature 에서 Full Screen Pass Renderer Feature 를 추가한다. Requirements 는 None 으로 둔다.
4. Pass Material 에 머티리얼을 넣고 Fetch Color Buffer 를 켠다. Injection Point 는 Bloom 이 없으면 Before Rendering Post Processing, Bloom 이나 톤 매핑 뒤에 점을 찍으려면 After Rendering Post Processing 으로 둔다.
5. 옵션 메뉴의 토글을 Full Screen Pass Renderer Feature 의 `SetActive` 에 연결해 효과를 끌 수 있게 한다.

## 확인
Game 뷰 전체가 45 도로 기운 옅은 점 격자로 바뀌고, 하늘처럼 중간 밝기인 곳에는 칸의 3분의 2 쯤 되는 점, 공의 밝은 윗부분 같은 하이라이트에는 작은 점, 어두운 그늘에는 서로 붙은 큰 점이 찍힌다. 줄 수를 내리면 점이 커지고, 방식을 CMYK 로 바꾸면 네 색 점이 겹친 작은 꽃 모양이 보이며, 잉크 세기를 0 으로 내리면 종이 색만 남는다.

## 기본 머티리얼 값
| 속성 | 뜻 | 값 |
|---|---|---|
| `_Mode` | 방식 | 칸 색 점 |
| `_Rows` | 줄 수 | 36 |
| `_Angle` | 각도 | 45 |
| `_DotGain` | 점 굵기 보정 | 0 |
| `_InkStrength` | 잉크 세기 | 0.4 |
| `_PaperColor` | 종이 색 | #F7F2E6 |
| `_InkColor` | 잉크 색 | #1F2A44 |

## 동작 단계
1. **돌린 칸 격자**: 칸 안 좌표를 회색 바탕에 빨강(가로), 초록(세로)으로 옅게 더해 보였다. 화면 전체를 덮는 정지 무늬라 칸 경계의 대비를 낮췄다. 줄 수를 20 쪽으로 내리면 잘 보인다. 아래 꼭짓점이 회색(칸 좌표 0, 0), 위 꼭짓점이 살구색(1, 1), 오른쪽 꼭짓점이 분홍(빨강 1, 0), 왼쪽 꼭짓점이 연두(초록 0, 1)인 마름모가 화면을 덮는다. 정사각 칸을 45 도 돌린 것이다. 가로가 긴 화면인데도 마름모가 찌그러지지 않는다. 좌표에 화면비를 곱한 뒤 돌렸기 때문이다. 각도를 0 으로 내리면 칸이 바둑판처럼 선다.
2. **칸 중심에서 읽은 색**: 칸 안의 모든 픽셀이 칸 가운데 한 점의 색을 읽어 화면이 비스듬한 마름모 모자이크가 되었다. 공의 윤곽과 바닥 격자의 경계가 칸 크기의 톱니로 끊긴다. 점 하나가 색 하나를 가져야 경계에서 점이 반쪽으로 잘리지 않는다.
3. **점 마스크**: 칸 색의 선형 밝기로 잉크 덮임(1 - 밝기)을 구하고, 원 면적이 덮임과 같도록 반지름을 덮임의 제곱근에 비례하게 그렸다. 화면 전체를 덮는 정지 무늬라 검은 점 대신 흰 바탕에 연한 회색 점(점 안이 바탕의 61% 밝기)으로 보였다. 하늘과 바닥은 칸의 3분의 2 쯤 되는 점, 큰 공 위쪽의 밝은 곳은 작은 점이다. 공 아래 그늘은 점이 칸 밖으로 넘쳐 서로 붙고 칸 귀퉁이에 작은 흰 구멍만 남는다. CMYK 를 고르면 네 판을 겹친 뒤 같은 하한을 걸어, 하늘에 시안과 연보라, 상자에 노랑이 섞인 작은 꽃 모양(로제트)이 보인다. 최종 화면은 이 점을 칸 색이나 잉크 색으로 칠해, 잉크 세기가 정한 밝기 아래로 내려가지 않게 종이에 찍은 것이다.

## 주의할 점
- 화면 전체를 덮는 정지 점 격자는 광과민 반응을 일으킬 수 있다. 게임 옵션으로 효과를 끌 수 있게 한다 (Full Screen Pass Renderer Feature 를 `SetActive(false)` 하거나 렌더러를 바꾼다. 에디터에서는 Renderer Feature 의 켜짐 상태가 에셋에 저장된다). 기본 잉크 세기 0.4 는 점 안이 종이의 61% 이상 밝기다 (종이 색까지 곱한 선형 밝기, 8비트 여유 1% 포함). 셰이더는 잉크 세기를 막지 않으므로 0.4 를 넘는 값(신문 흑백 프리셋 0.92)은 이용자가 고르는 옵션으로만 둔다. 점을 움직이는 연출(시간으로 흘리기, 점 크기 반복)은 넣지 않는다.
- Bloom 과 톤 매핑 뒤에 점을 찍으려면 Injection Point 를 After Rendering Post Processing 으로 둔다. Before Rendering Post Processing 이면 점 가장자리가 Bloom 에 번진다. After Rendering Post Processing 과 FXAA, 업스케일(FSR, STP)의 순서는 확인하지 않았다.
- Screen Space - Overlay 캔버스의 UI 는 이 패스 뒤에 그려져 점이 덮이지 않는다. 글자는 읽기 쉽게 남는 편이 낫다. UI 까지 덮으려면 Screen Space - Camera 캔버스를 쓴다. Renderer Feature 는 그 렌더러를 쓰는 모든 카메라와 Scene 뷰에 걸리므로, 미니맵이나 렌더 텍스처 카메라는 다른 렌더러를 쓰게 한다.
- XR 에서는 이 패스를 끈다. 머리에 붙은 화면 공간 점 무늬는 두 눈의 무늬가 장면 깊이와 맞지 않아 화면에 붙은 막처럼 보인다 (추정, 실기기 미확인). XR 에서는 같은 원리를 물체 표면의 음영(월드 공간 좌표)으로 옮긴다.
- 비용은 픽셀마다 화면 텍스처 읽기 2번(흑백, 칸 색: 칸 중심 1번과 원본 1번) 또는 5번(CMYK: 판마다 1번과 원본 1번)이다. 모바일에서는 흑백이나 칸 색을 권한다. CMYK 의 판 읽기는 모드 분기 안에 있어 밉 0 으로 읽고(`SAMPLE_TEXTURE2D_X_LOD`), 점 가장자리 폭도 `fwidth` 대신 줄 수 × 픽셀 크기로 계산한다. 분기 안에서 미분을 쓰면 Unity 가 경고를 낸다. 칸 크기는 `_ScreenSize`(카메라 대상 높이)의 줄 수라 Render Scale 이나 동적 해상도를 바꿔도 칸 모양은 같고, 칸이 4 픽셀보다 작아지면 원본이 섞이기 시작해 3 픽셀에서 점이 사라진다.

## 흔한 실수
- **화면 전체가 밝고 색이 빠져 보인다**: 반지름을 밝기에 선형으로 두면(`r = 0.5 × (1 - 밝기)`) 점 면적이 그 제곱이라 중간 톤의 잉크가 크게 모자란다 (덮임 0.5 에서 20%). 칸 한 변을 1 로 두고 `r = sqrt(덮임 / π)` 로 면적을 덮임에 맞춘다. 덮임이 78.5% 를 넘으면 원이 칸 밖으로 넘치므로, 그 위에서는 반대각선 0.707 까지 키워 귀퉁이의 흰 구멍이 줄어들게 한다.
- **물체 경계에서 점이 반달처럼 잘리고 지글거린다**: 픽셀마다 자기 자리의 색을 읽어 덮임을 구하면 칸 하나 안에서 반지름이 바뀌어, 색 경계를 지나는 점이 반쪽만 그려진다. 칸 좌표를 `floor + 0.5` 로 칸 중심에 모은 뒤 거꾸로 돌려 화면 uv 로 되돌리고, 그 한 점에서만 읽는다. CMYK 는 판마다 자기 각도의 칸 중심에서 따로 읽는다.
- **중간 톤의 점이 작아 사진이 바랜 듯 밝다**: 감마(sRGB) 값으로 덮임을 계산한 경우다. sRGB 0.5 는 선형 밝기 0.21 이라 실제로는 79% 를 덮어야 같은 밝기로 보이는데 50% 만 덮는다. URP 의 Linear 색 공간에서는 화면 텍스처가 선형으로 읽히므로 읽은 값을 그대로 쓰고, 표시용 sRGB 로 바꾼 값이나 Gamma 색 공간 프로젝트의 값으로 덮임을 구하지 않는다.
- **점이 가로로 늘어난 타원이거나 해상도마다 점 크기가 다르다**: uv 에 바로 칸 수를 곱하면 가로가 긴 화면에서 칸이 직사각이 되고 점이 타원이 된다. 화면 가운데를 원점으로 `float2(aspect, 1)` 을 곱한 뒤 돌린다. 칸 크기를 픽셀로 정하면 1080p 와 720p 에서 점 개수가 달라지므로 화면 높이의 줄 수로 정한다. 칸이 몇 픽셀 안 되면 점이 픽셀과 부딪쳐 얼룩이 되므로 4 픽셀부터 원본을 섞기 시작해 3 픽셀에서 원본으로 둔다.
- **점 무늬 화면이 눈을 피곤하게 한다**: 화면 전체를 덮는 정지 점 격자도 줄무늬처럼 광과민 반응을 일으킬 수 있다. 점 안이 점 밖의 60% 이상 밝기가 되게 잉크 세기를 0.4 이하로 둔다. 비율은 잉크만이 아니라 종이 색까지 곱한 최종 색의 선형 밝기로 잰다 (잉크만 재서 맞추면 색이 강한 종이와 잉크의 조합에서 최종 비율이 60% 아래로 내려간다). 잉크를 섞는 비율로만 낮추면 밝은 칸 색까지 함께 바래므로, `L(종이 × 잉크)` 가 `L(종이) × (1 - 잉크 세기)` 보다 어두울 때만 잉크를 흰색 쪽으로 올려 맞추고, 8비트 반올림에 대비해 1% 여유(0.4 에서 61%)를 둔다. CMYK 는 판이 겹친 결과에 건다. 단계 보기처럼 마스크를 보여 주는 화면도 흰 바탕에 검정으로 칠하지 않는다. 점을 시간으로 움직이거나 크기를 계속 바꾸지 않는다. 신문 흑백처럼 대비가 높은 모양은 잠깐 쓰는 연출이나 이용자가 고르는 옵션으로만 두고, 게임 옵션에서 효과를 끌 수 있게 한다.

## 변형 예시
- 일시정지 화면이나 만화풍 컷신 배경에만 하프톤을 잠깐 걸고, 평소에는 꺼 두고 싶다.
- 외곽선 후처리와 함께 써서 만화 인쇄 느낌을 만들고 싶다. 외곽선은 점 위에 또렷하게 남게 하고 싶다.
- 화면 전체 대신 캐릭터 그림자 부분에만 점을 찍고 싶다 (툰 음영의 어두운 쪽을 월드 공간 점으로 바꾸는 표면 셰이더 변형).
- 옵션 메뉴에 필터 끄기, 은은한 질감, 만화 인쇄 세 단계를 두고 싶다.

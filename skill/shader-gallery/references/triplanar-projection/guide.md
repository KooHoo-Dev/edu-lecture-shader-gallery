# 삼평면 투영 (Triplanar Projection)

UV 없이 세 축에서 텍스처를 투영한다

무대 종류: 메시. 난이도 2/3. 기법: 삼평면 투영, 월드 좌표, 법선 가중치, 텍스처.

## 파일
- `TriplanarProjection.shader`
- `core.hlsl`
- `TriplanarTiles.png`

모두 프로젝트의 `Assets/Shaders/triplanar-projection/` 에 복사한다.

## 넣는 순서
1. `TriplanarProjection.shader`, `core.hlsl`, `TriplanarTiles.png` 를 `Assets/Shaders/triplanar-projection/` 에 둔다.
2. Project 창에서 `TriplanarTiles.png` 를 고르고 Inspector 에서 Texture Type 을 Default, sRGB (Color Texture) 를 켬, Wrap Mode 를 Repeat, Filter Mode 를 Bilinear 로 두고 Apply 를 누른다.
3. 셰이더를 우클릭해 Create > Material 로 머티리얼을 만들고, 타일 텍스처 칸에 `TriplanarTiles.png` 를 넣는다.
4. 머티리얼을 절벽, 바위, 상자 같은 MeshRenderer 에 넣는다. UV 가 없거나 엉망인 메시여도 된다.
5. 움직이지 않는 지형이면 투영 공간을 World, 움직이거나 도는 소품이면 Object 로 둔다.

## 확인
한 축으로 길게 늘린 큐브나 원기둥에 넣어도 옆면의 돌이 늘어나지 않는다. 물체를 Y 축으로 돌리면 World 에서는 무늬가 표면 위를 미끄러지고 Object 에서는 함께 돈다. 섞임 날카로움을 1 로 내리면 둥글거나 비스듬한 면에서 줄눈이 이중으로 비친다.

## 기본 머티리얼 값
| 속성 | 뜻 | 값 |
|---|---|---|
| `_Space` | 투영 공간 | 월드 |
| `_TileSize` | 타일 크기 | 1 |
| `_BlendSharpness` | 섞임 날카로움 | 8 |
| `_Tint` | 색조 | #FFFFFF |

## 동작 단계
1. **세 축 가중치**: 법선 세 성분의 절댓값을 거듭제곱하고 합이 1 이 되게 나눈 값을 색으로 본다. X 축을 보는 옆면은 빨강, 앞뒤(Z)는 파랑, 윗면(Y)은 초록이다. 이 무대의 카메라는 상자 윗면과 거의 같은 높이라 초록은 보이지 않는다. 월드 공간에서는 상자가 돌아 면이 축에서 비스듬해지면 빨강과 파랑이 섞여 보라나 분홍이 된다. 오브젝트 공간으로 바꾸면 상자가 돌아도 면 색이 그대로다.
2. **한 축 투영**: X 축 투영(`zy` 좌표) 하나만 상자 전체에 씌운 모습이다. 1단계에서 빨강이던 옆면은 돌이 반듯하지만, 파랑이던 앞면은 `z` 가 거의 변하지 않아 같은 줄이 가로로 길게 늘어난다. 평면 투영 하나로는 모든 면을 덮을 수 없다.
3. **섞은 결과**: Y, Z 축 투영까지 세 장을 1단계 가중치로 섞었다. 면마다 늘어나지 않는 투영이 대부분을 차지해 모든 면에 돌이 반듯하게 놓인다. 상자 면이 45도 가까이 돌면 두 투영이 반반 섞여 줄눈이 이중으로 비친다. 섞임 날카로움을 올리면 그렇게 보이는 각도가 좁아지고, 1 로 내리면 넓어진다.
4. **최종 조명**: 섞은 색에 조명(`i.lighting`)을 곱해 면마다 밝기가 달라진다. 투영 공간을 바꿔 보면 차이가 보인다. 월드는 돌 무늬가 공간에 고정되어 도는 상자 면 위를 미끄러지고, 오브젝트는 줄눈이 상자 모서리에 맞춰 붙어 함께 돈다.

## 주의할 점
- 이 셰이더는 불투명 3D 메시용이다. 패스가 `UniversalForwardOnly` 라 2D Renderer 에서는 그려지지 않는다. 3D 프로젝트에서 쓴다.
- 머티리얼의 타일 텍스처 칸이 비어 있으면 흰색 기본 텍스처가 쓰여 무늬 없이 단색으로 보인다. `TriplanarTiles.png` 를 sRGB (Color Texture) 켬, Wrap Mode Repeat, Filter Mode Bilinear 로 임포트해 그 칸에 넣는다. Wrap Mode 가 Clamp 이면 0~1 밖의 좌표에서 가장자리 픽셀이 길게 번진다.
- Static 으로 표시해 정적 배칭되면 여러 메시가 하나로 합쳐지며 정점이 월드 위치로 구워진다. 이때 Object 공간 무늬는 원래 모양과 달라진다. 정적 배칭되는 지형과 바위에는 World 를 쓴다.
- 텍스처를 세 번 읽으므로 일반 텍스처 재질보다 비싸다. 모바일에서 넓은 지형에 쓸 때는 가중치가 거의 0 인 축의 샘플을 건너뛰는 식의 최적화를 고려한다.
- 반대쪽 면(예: +X 와 -X)은 같은 좌표를 쓰므로 무늬가 좌우로 뒤집혀 보인다. 돌 타일처럼 방향이 없는 무늬는 티가 나지 않지만 글자나 화살표는 뒤집힌다. 그럴 때는 법선 부호(`sign`)로 그 축의 u 를 뒤집는다.
- 월드 좌표가 아주 큰 곳(원점에서 수 km)에서는 실수 정밀도가 떨어져 무늬가 떨린다. 큰 월드에서는 타일 크기 단위로 원점을 옮기거나 오브젝트 공간을 쓴다.

## 흔한 실수
- **옆면에 세로 줄무늬가 길게 늘어난다**: 위에서 내려다본 좌표(`xz`) 하나로만 투영하면 옆면은 같은 줄을 위아래로 끌어 쓴다. 절벽, 원기둥, 바위 옆면에서 생긴다. 세 축으로 투영해 법선 방향 가중치로 섞는다.
- **경계 부분만 밝거나 어둡게 얼룩진다**: `pow(abs(N), 날카로움)` 의 세 값은 합이 1 이 아니다. 날카로움이 2 보다 크면 합이 1 보다 작아져 경계가 어두워지고, 1 이면 1 보다 커져 밝아진다. 세 값의 합으로 나눠 정규화한다.
- **움직이는 물체 위로 무늬가 미끄러진다**: 월드 좌표로 투영하면 무늬가 공간에 고정되어 물체가 움직이거나 돌 때 표면 위를 흐른다. 지형, 절벽처럼 움직이지 않는 것에만 쓰고, 움직이는 소품은 오브젝트 공간을 고른다. 월드 공간에서 돌아간 평평한 면은 법선이 두 축 사이에 놓여 두 투영이 겹치므로 줄눈이 이중으로 비치기도 한다. 이 무대의 상자를 월드와 오브젝트로 번갈아 보면 둘 다 확인할 수 있다.
- **크기를 키우면 돌도 커지거나 한쪽으로 늘어난다**: 오브젝트 공간 투영은 Transform 의 Scale 을 함께 받는다. 균일하게 키우면 돌도 커지고, 한 축만 키우면 그 방향으로 늘어난다. 크기가 제각각인 바위에 같은 돌 크기를 원하면 월드 공간을 쓴다.
- **노멀맵을 같은 식으로 섞었더니 조명이 엉뚱하다**: 노멀맵 색은 각 투영 평면의 탄젠트 공간 값이라 그대로 섞으면 방향이 맞지 않는다. 축마다 성분 순서를 바꿔 월드 법선으로 돌린 뒤 섞어야 한다 (whiteout, reoriented 블렌딩). 이 표본의 범위 밖이며 참고 자료의 글을 본다.

## 변형 예시
- 윗면에는 잔디, 옆면에는 바위 텍스처가 나오게 하고 싶다.
- 노멀맵도 삼평면으로 입혀 돌 줄눈에 음영이 지게 하고 싶다.
- 텍스처 세 번 읽기가 부담돼 모바일용으로 가볍게 하고 싶다.
- 눈이 위에서 쌓인 것처럼 윗면에만 흰색을 덮고 싶다.
- 글자가 들어간 텍스처가 뒤쪽 면에서 뒤집히지 않게 하고 싶다.

## Shader Graph 에서 쓰기
Shader Graph 에는 같은 일을 하는 Triplanar 노드가 있다. Tile 이 타일 배율(이 표본의 타일 크기의 역수), Blend 가 섞임 날카로움이다. Position 과 Normal 입력에 Object 공간 Position, Normal Vector 노드를 넣으면 오브젝트 공간 투영이 된다. 이 셰이더의 `triplanarWeights` 를 Custom Function 으로 불러 가중치만 다른 계산에 쓸 수도 있다.
